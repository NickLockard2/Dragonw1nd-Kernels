`clang_version=manifest` deliberately uses the Clang toolchain committed in the
pinned OnePlus/CodeLinaro manifest. An initial build with the newer external
`aosp-clang-r614150` toolchain failed because Clang 23 promotes legacy OnePlus
driver declarations to fatal `-Wstrict-prototypes` errors. The phone's stock
5.15.197 kernel identifies Android Clang 14.0.7 (`r450784e`), so the manifest
toolchain is the compatibility- and provenance-preserving choice; no driver
warning suppression or behavioral source patch is applied.

The OP11 device configuration requests `-mtune=cortex-a715`, but Android
Clang 14.0.7 predates that CPU name and rejects the option. The build action
therefore compiles a minimal AArch64 probe with the selected compiler and adds
the optional `-mtune` only when supported. With the stock-matched manifest
compiler it uses Clang's default AArch64 tuning. This changes optimization
tuning only; it does not suppress diagnostics, modify driver behavior, or
change the pinned source revisions.

The build is not considered successful until the workflow completes, the artifacts are downloaded, their SHA-256 hashes are recorded, the compiled kernel reports `5.15.197`, and a nonpersistent `fastboot boot` canary succeeds on the target device. No persistent partition write is authorized by this build workflow.
